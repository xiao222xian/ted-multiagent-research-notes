# 指标定义：分数究竟测到了什么

## 四个主要体征

体征级分析使用 proptosis（眼球突出）、lid_retraction（眼睑退缩）、lid_edema（眼睑水肿）、conjunctival_edema（结膜水肿）。这是本实验的评价范围，不是全部眼科表现。

## 状态与报告 micro-F1

状态端以 JSON 中值为 `present` 的体征作为阳性；其他值及解析失败在该二值体征指标中按非阳性处理。报告端使用词汇匹配和局部否定规则提取阳性。

参考标签来自参考眼科状态，并非本次公开整理时重新做的独立医生标注。

```text
precision = TP / (TP + FP)
recall = TP / (TP + FN)
micro_F1 = 2TP / (2TP + FP + FN)
```

对 11 条 TED 的四个体征先累加 TP/FP/FN 再计算，不是病例 F1 的简单平均。JSON 合法率、逐字段准确率、病例平均阳性召回与这里的 micro-F1 不是同一指标。

## 状态—报告不一致比例

原实现对 TED 子集的每个体征检查状态阳性与报告阳性是否不同：

```text
disagreement = sum(state_positive != report_positive) / (11 * 4)
```

它同时计算“报告额外阳性”和“报告遗漏状态阳性”。因此，0.477 约为 21/44，0.205 约为 9/44；这不是“47.7% 的患者被误诊”。一致性也不等于体征正确性。

## 非 TED 阳性体征出现比例

旧文件把该项称为 `any_final_report_sign_fp`。核对代码后可知，它直接计算 15 条非 TED 样本中，至少出现一个相关阳性体征的病例比例，没有逐体征检查参考阴性标签。

非 TED 病例仍可能真实存在眼睑水肿等表现。这里将其改称**非 TED 阳性体征出现比例（历史 FP 代理指标）**，作为偏差排查信号，不当作已确认的临床假阳性率。

```text
proxy = number_of_non_TED_reports_with_any_tracked_positive_sign / 15
```

例如 0.867 对应 13/15，0.667 对应 10/15。只有确认这些体征在对应病例中真实阴性后，才能作更严格的误报解释。

旧负控文件还给出 TED 词汇判断代理，但它受关键词、否定/建议词以及诊断标签输入影响，公开主表不把它作为诊断准确率发布。

## clinical_score 的实际实现

核对评分代码，主要逻辑是统计参考报告和生成报告各自命中的医学关键词**数量**，再计算数量比并截断到 1：

```text
score = min(generated_keyword_count / reference_keyword_count, 1)
```

参考命中数为 0 时有单独回退分支。它不是逐个匹配相同关键词的集合召回，也没有完整处理否定或判断医学陈述是否正确。不同关键词也可能得到相同数量，错误或冗余内容也可能得高分。

因此，公开结果表称其为“关键词数量代理分”，不能把 1.000 写成 100% 临床准确率或医生评分通过。更早的其他辅助脚本还有不同回退实现，跨运行时必须记录实际使用的评分函数。

## 过滤后不一致为 0 的边界

交集规则 `F = R AND S` 必然消除 `F=1, S=0`，但当 `S=1, R=0` 时仍然有 `F=0, S=1` 的不一致。当前 C3 样本上观察到 0，不能当作该规则的一般定理。

过滤后的关键词代理分没有重新计算；公开主表留空，避免把原 C3 的 1.000 当成过滤后新报告质量。

## 文本解析差异

原体征评估与过滤脚本的否定窗口分别使用 12 和 16 个字符，并且否定词表、体征同义词略有不同。解析结果可能受此影响。未统一解析器重新评估前，不应假定所有差异只来自过滤规则或模型。
